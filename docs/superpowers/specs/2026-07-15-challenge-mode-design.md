# Challenge Mode — Design

**Date:** 2026-07-15
**Status:** Approved

## Goal

Let friends compete on the identical puzzle to see who solves it faster, asynchronously: share a link, everyone races the same cube on their own device, compare times. No server, no accounts — everything stays inside the single self-contained `index.html`.

## Decisions (from brainstorming)

| Question | Decision |
|:--|:--|
| Competition style | Async challenge links (Wordle-style), not real-time or hot-seat |
| Scoring | Time only; timer starts on first move |
| Retries | Allowed; shared result includes attempt number |
| Solver during a run | Voids the attempt (timer stops, path resets, attempt consumed) |
| Hints during a run | Free, but hint button has a 10-second cooldown; free play unchanged |
| Link format | Encode the puzzle itself (checkpoint placement), not an RNG seed |

## 1. Challenge codes & links

A puzzle is fully defined by its 6 checkpoint cell ids in order (checkpoint 1 → 6, from `numByCell`/`startCell`). Each id is 0–23, so each fits in one base-36 character: every puzzle compresses to a **6-char code** like `a3k9f2`.

- **Encode:** `code = checkpointCellIds.map(id => id.toString(36)).join('')` where index 0 is checkpoint 1's cell (`startCell`).
- **Decode:** parse 6 base-36 chars → ids; valid iff exactly 6 chars, all ids in 0–23, all distinct.
- **URL:** `index.html#z=<code>`. On load, a valid `#z=` hash rebuilds that exact puzzle and enters challenge mode. The hash is also updated whenever a new puzzle is generated, so the current puzzle is always shareable.
- **UI:** a "⚡ Challenge" button in play mode copies the current puzzle's link to the clipboard (with a confirmation toast) **and arms challenge mode locally** (path resets to the start cell, timer armed) — so the challenger races the same puzzle under the same rules as the friends they sent it to.
- **Entering challenge mode:** via a `#z=` link on load, or via the ⚡ Challenge button. All other play (random puzzles you haven't challenged on) remains untimed free play.

Codes generated by the app always come from a valid Hamiltonian path, so they are always solvable; no solvability check is run on decode.

## 2. Challenge run & timer

Challenge state: `{ code, attempts, startTs, running }`.

- Timer **starts on the first path extension** (not page load), stops when all 24 cells are filled (`userWin`).
- Live display in the HUD as `m:ss.t`, alongside the existing progress counter, visible only while a challenge is active.
- **Reset** abandons the current run; the next first move begins attempt N+1.
- Attempt counts and personal-best times are stored in `localStorage` keyed by code, so they survive reloads.
- **New puzzle** during a challenge exits challenge mode (generates a fresh random puzzle and updates the hash to the new code — the new puzzle is itself immediately shareable, but the previous challenge's run ends).

## 3. Fairness rules

- **Solver voids the run:** switching to solver mode while a challenge run is active stops the timer, resets the path to the start cell, and consumes the attempt. A brief toast explains why. The solver remains fully usable — you just can't claim the time.
- **Hint cooldown:** during an active challenge run, using a hint disables the hint button for 10 seconds, with a countdown shown on the button (e.g. `💡 7s`). Hints carry no time penalty and are not shown in the shared result. Outside challenge runs, hints behave exactly as today.

## 4. Results

On solving during a challenge, the existing win overlay additionally shows:

- final time (`m:ss.t`),
- attempt number,
- personal best for this code (from `localStorage`),
- a **Copy result** button producing a paste-ready snippet:

```
Zip Cube ⚡ 0:47.3 · attempt 2
https://…/index.html#z=a3k9f2
```

Friends open the link, race the identical cube, and paste their time back. That is the entire competition loop.

## 5. Error handling

- **Malformed code** (wrong length, non-base-36 chars, out-of-range or duplicate ids): fall back to a random puzzle and show a toast ("invalid challenge link").
- **Clipboard failure** (no `navigator.clipboard`, permission denied): fall back to showing the text in a `prompt()` for manual copy.

## 6. Implementation constraints

- All logic stays inside the existing single IIFE in `index.html`; no new files, no dependencies.
- New UI colors use the existing semantic CSS custom-property tokens (dark + light themes); no hardcoded colors in JS.
- New buttons/HUD elements follow the existing `.playOnly` mode-visibility pattern.
- Mode/theme class handling continues to use `classList` so the `light` class survives.

## 7. Testing

No test framework exists; verification is manual in the browser (and headless via the project's `verify` skill):

1. Link round-trip: generate puzzle → copy link → open in fresh tab → identical checkpoint layout.
2. Timer starts on first move, stops on solve; shown time matches wall clock.
3. Reset + re-solve increments attempt number; attempts persist across reload.
4. Entering solver mid-run voids the attempt and shows the toast.
5. Hint cooldown counts down 10s during a run; hints unaffected in free play.
6. Malformed `#z=` values fall back gracefully.
7. Copy result / copy link snippets are correct; clipboard fallback works.
8. All new UI renders correctly in both dark and light themes.
